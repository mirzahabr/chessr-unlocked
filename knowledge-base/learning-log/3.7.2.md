# Learning log — 3.7.2

## Architectural discoveries

- **The engines left the package.** Through 3.4.0 the build carried ~184 MB of vendored
  engines. 3.7.2 carries `engine/explanation-engine.wasm` (26 MB) and two copies of a
  157 KB `sealed_core_bg.wasm`. Everything else is UI.
- **Analysis is now a server product.** `suggestion_request`, `maia3_request`,
  `engine_eval_request`, `analysis_request` and `chesscom_review` travel over
  `wss://api.chessr.io/ws` and are answered there. The client only renders.
- **The socket is sealed.** A Rust `sealed_core` module performs `handshake_start` /
  `handshake_finish`, the server answers `kex`, and frames become `{d: sealed_core.seal(…)}`.
  A rejected identity closes the socket with code 4007.
- **Three queues before anything is sent:** socket not open, handshake not finished, and no
  `auth_ok` yet. Without a token the third queue simply never drains usefully.
- **New gates:** update-required (`GET /health`), feature flags (`GET /flags`), region
  election, guidelines acceptance, account linking (`linked_accounts`), daily quotas in
  review replies.
- **Build namespace.** CSS classes, the custom element, postMessage verbs and even an icon
  filename carry a per-build prefix (`x9110e26d`). It is randomized per build, so any future
  version will break selectors written against this one.

## Confirmed assumptions

- Content scripts, manifest shape, DNR rules (now four, `sentry.io` added) and the
  shadow-root overlay are structurally the same as 3.4.0.
- The auth store, `initialize`, `fetchPlan`, `signOut`, the premium/free predicates and the
  link gate are still the right edit points — the same eight edits reproduce a login-free
  panel in 3.7.2.

## Disproven assumptions

- **"The unlock can unlock the engines."** It cannot: there is no engine to unlock. The
  engine predicate still needs patching so the dropdown is not disabled, but that is
  cosmetic. This is the single most important correction to the repository's premise.
- **"Strict-mode Stream Mode artifact is version-specific."** It was a 3.4.0 pipeline bug,
  not a property of the code; 3.7.2's output parses as a module and was checked explicitly.

## Tooling fixes

- **`--no-jsx` is mandatory.** The first 3.7.2 run used webcrack's default JSX decompiler,
  which rewrote `jsx()` calls into `<div …>` syntax and produced two unparseable bundles.
  Re-ran with `--no-jsx`; both parse with `node --check` and under `vm.SourceTextModule`.
- **The patch generator must be deterministic.** Hand-editing 2.7 MB bundles is not
  reviewable, so the unlock is generated by `scripts/unlock-3.7.2.py`; the script also
  formats its inserts exactly as Prettier would, so no separate formatting pass is needed.
- **Indentation differs between the two bundles** (content.js nests the store at 4 spaces,
  the Stream bundle at 2). Anchors are written indentation-agnostic; a hard-coded indent
  silently mis-edits the Stream bundle.
- **Headless Chrome no longer loads extensions from the branded build** (Chrome 137+
  removed `--load-extension`). Verification uses a Chromium build from
  `@puppeteer/browsers`, driven over CDP; see `docs/verification.md`.

## Known limitations

- Server-side analysis cannot be unlocked client-side. Documented in the README, the
  version README, the unlock manifest and §8 of the project report — four places, because
  this is the fact a reader is most likely to be misled about.
- The auth screen's logo path (`/icons/x9110e26d-logo.png`) 404s in the upstream package;
  recorded rather than repaired, since the unlock removes that screen.
